### 1. ביקורת איכות UX מלאה (UX, Hick's Law, Mobile & RTL Audit)

**מתי להשתמש?** כשרוצים לסקור אפליקציה קיימת ולזהות נקודות תורפה, עומס קוגניטיבי, בעיות RTL או קשיים בטלפונים ניידים.

```markdown
אתה מומחה UX/UI וביקורת מוצר. בצע ביקורת איכות (Audit) מקיפה לאפליקציה [שם האפליקציה] / לקוד המצורף:

---
### רשימת תצליב לבדיקה (Audit Checklist):

1. **חוק היק (Hick's Law Checklist):**
   - האם יש יותר מ-5 אפשרויות בחירה במסך בודד?
   - האם הפעולה הראשית (Primary CTA) בולטת בצורה ברורה מעל שאר הכפתורים?
   - האם ניתן לצמצם שדות בטפסים או לחלק אותם לשלבים (Multi-step)?

2. **בדיקת RTL ושפה עברית (RTL & Language Check):**
   - האם יישור הטקסט, האייקונים והסרגלים עובדים מימין לשמאל באופן טבעי?
   - האם יש טקסטים קטומים, סימני פיסוק הפוכים (כגון סוגריים הפוכות) או שילוב אנגלית/עברית שובר שורות?
   - האם כפתורי "הקודם" ו"הבא" מורים לכיוון הנכון (הבא = שמאלה ב-RTL)?

3. **בדיקת מובייל (Mobile Responsiveness Check):**
   - האם רכיבים נלחצים (Touch Targets) הם בגודל של לפחות 44x44 פיקסלים?
   - האם הטקסטים קריאים ללא צורך בזום?
   - האם יש גלילה אופקית לא מתוכננת (Horizontal Overflow)?

ספק דוח ממצאים מפורט בעברית + הצעות לתיקון קוד מיידי.
[הדבק כאן את הקוד או תיאור המסכים]
```

### 2. הוספת פיצ'ר חדש ללא שבירת תזרימים (Safe Feature Addition)

**מתי להשתמש?** כשנדרש להוסיף תכונה חדשה למערכת עובדת מבלי לעמוס על ה-UI ומבלי לשבור קוד קודם.

```markdown
אתה ארכיטקט תוכנה ומפתח פרונטאנד בכיר. אני רוצה להוסיף את הפיצ'ר הבא:
**פיצ'ר חדש:** [תיאור הפיצ'ר החדש, למשל: ייצוא דוחות ל-PDF / שליחת תזכורת ב-WhatsApp]
**האפליקציה הקיימת:** [שם האפליקציה]

---
### הוראות לביצוע:
1. **ניתוח אימפקט (Impact Analysis):** אילו רכיבים, קבצים או ישויות נתונים קיימות מושפעים מהשינוי?
2. **אינטגרציה נקייה המומרת ל-UI:**
   - היכן למקם את כפתור/אלמנט הפיצ'ר החדש כך שזה לא יפר את חוק היק ולא יעמיס על המשתמש?
   - שמור על שפות הסטייל והעיצוב הקיימות של האפליקציה.
3. **שמירה על לאנגזיה ו-Regression:** ודא שכל הפונקציות הקיימות ממשיכות לעבוד ללא שינוי ב-Signatures או ב-State.

החזר את תוכנית ההטמעה + השינויים הנדרשים בקוד.
[הדבק כאן את הקוד הרלוונטי]
```

### 3. סבב שיפור ביצועים ו-Cache-Busting (Performance & Cache Pass)

**מתי להשתמש?** כשהאפליקציה מציגה איטיות, בעיות בטעינת גירסאות חדשות בדפדפן המשתמש (Stale Assets), או קריאות רשת מרובות.

```markdown
אתה מומחה אופטימיזציית פרונטאנד וביצועים (Web Performance & Caching Expert).
תפקידך לבצע סבב שיפור ביצועים וניקוי Cache עבור [שם האפליקציה]:

---
### משימות האופטימיזציה:

1. **מניעת בעיות Caching (Cache-Busting):**
   - הגדרת אסטרטגיית Versioning מבוססת Build Hash לקבצי JS/CSS.
   - וידוא קריאות ה-API משתמשות ב-Headers מתאימים (`Cache-Control: no-cache` או הוספת timestamp `?v=...` בקריאות דינמיות).

2. **ייעול טעינת רכיבים ומשאבים:**
   - הטמעת Lazy Loading לרכיבים כבדים ולתמונות.
   - צמצום קריאות חוזרות לשרת (Debouncing שדות חיפוש, Memoization של חישובים).
   - שימוש ב-Skeleton Screens לשיפור הביצועים הנתפסים (Perceived Performance).

3. **ניקוי זיכרון ו-Listeners:**
   - ניקוי Event Listeners ו-Intervals בעת Unmount של קומפוננטות.

בצע סקירה של הקוד הבא והצע שיפורים ישירים:
[הדבק את הקוד לבדיקה]
```

### 4. ניקוי קוד ופירוק קומפוננטות (Code Cleanup & Refactoring)

**מתי להשתמש?** כשהקוד הופך לארוך מדי (Spaghetti Code), קומפוננטה בודדת מכילה מאות שורות, או שיש כפילויות קוד.

```markdown
אתה מומחה Clean Code ו-React/JavaScript Architecture.
בצע רפקטורינג לקוד הבא של [שם האפליקציה]:

1. **פירוק קומפוננטות (Decomposition):** חלק קומפוננטה גדולה לקומפוננטות משניות קטנות וייעודיות (למשל: הפרדת ה-Header, ה-Form וה-List).
2. **הוצאת לוגיקה לעזרים (Extract Custom Hooks / Utilities):** הוצא קריאות API, ניהול State מורכב ופונקציות עזר מחוץ לרכיב ה-UI.
3. **מניעת כפילויות (DRY - Don't Repeat Yourself):** אחד אלמנטים חוזרים לרכיבים שימושיים (Reusable UI Components).
4. **שיפור הקריאות:** הוסף שמות משתנים משמעותיים והערות הסבר קצרות בעברית.

```

### 5. ביקורת נגישות ותאימות דפדפנים (Accessibility & Cross-Browser Audit)

**מתי להשתמש?** לוודא שהאפליקציה נגישה לבעלי מוגבלויות ותואמת לכל הדפדפנים והמכשירים.

```markdown
אתה מומחה נגישות באינטרנט (Web Accessibility - WCAG 2.1 AA) ותאימות דפדפנים.
סקור את [שם האפליקציה] / הקוד המצורף וודא:

1. **יחס ניגודיות (Color Contrast):** ניגודיות מספקת בין הטקסט לריקע לפי התקן.
2. **ניווט מקלדת (Keyboard Navigation):** אפשרות להגיע לכל אלמנט אינטראקטיבי ב-Tab, עם Focus Ring בולט.
3. **תגיות ARIA וסמנטיקה:** שימוש נכון ב-`<button>`, `<main>`, `<nav>`, `aria-label` ו-`aria-expanded`.
4. **קוראי מסך בעברית:** התאמת הקוד לקוראי מסך הפועלים בעברית (הגדרת `lang="he"` ו-`dir="rtl"`).

ספק דוח קצר ותיקוני קוד נדרשים.
[הדבק כאן את הקוד]
```
