### 1. יצירת שפת עיצוב מלאה וטוקנים (Design System & Tokens)

**מתי להשתמש?** כשרוצים להגדיר חוקי עיצוב אחידים (צבעים, טיפוגרפיה, מרווחים, צללים) לפני בניית הרכיבים.

```markdown
אתה מעצב ממשקים בכיר (Lead UI/UX Designer). צור שפת עיצוב מלאה (Design Tokens & Component Rules) עבור [שם האפליקציה]:

### 1. פלטת צבעים (Color Palette)
- **Primary Color:** [צבע מוביל, למשל: `#0d9488` Teal]
- **Secondary / Accent:** [צבע משלים, למשל: `#f59e0b` Amber]
- **Neutral Colors:** צבעי רקע (Light/Dark), גווני אפור לטקסט ולגבולות.
- **Feedback Colors:** ירוק להצלחה (`#10b981`), אדום לשגיאה (`#ef4444`), צהוב לאזהרה (`#f59e0b`).

### 2. טיפוגרפיה ועברית (RTL Typography)
- גופנים מומלצים לעברית (Heebo, Rubik או Assistant).
- סולם גדלים (Font Scale): כותרת ראשית (H1), כותרת משנה (H2), טקסט רגיל (Body), טקסט קטן (Caption).
- משקלי גופן (Font Weights): 400 (Regular), 500 (Medium), 700 (Bold).

### 3. מרווחים ורדיוסים (Spacing & Radius)
- גריד 8px (Spacing Scale: 4px, 8px, 16px, 24px, 32px, 48px).
- רדיוס פינות (Border Radius): למשל `rounded-xl` (12px) לכפתורים וכרטיסיות.
- צללים (Box Shadows): צל עדין לכרטיסיות, צל מורם למודאלים/דרופדאונים.

הנפק את ההגדרות כקוד CSS Variables או Tailwind Config, בצורה נקייה ומוכנה להטמעה.
```

### 2. סגנון אפליקציית ילדים / חינוך (Children's App Style)

**מתי להשתמש?** לפיתוח אפליקציות המיועדות לילדים, תלמידים או משחקי למידה (Gamification).

```markdown
אתה מעצב UI המתמחה בממשקים לילדים ולחינוך. עצב את הממשק של [שם האפליקציה] בסגנון חווייתי, צבעוני ונגיש:

### דגשי העיצוב:
1. **צבעוניות חמה ושמחה:** פלטת צבעים עשירה אך נעימה לעין (גווני תכלת, כתום רך, ירוק פסטל, צהוב שמש).
2. **צורות רכות ונגישות:** פינות עגולות במיוחד (`rounded-2xl` עד `rounded-full`), כפתורים תלת-ממדיים או עם אפקט לחיצה בולט (Button Push Effect).
3. **אייקונים ואלמנטים ויזואליים:** אייקונים גדולים, איורים ידידותיים, ואלמנטים של משחוק (Badges, Stars, Progress Bars).
4. **טיפוגרפיה:** גופן עברי עגול וקריא (כגון 'Rubik' או 'Varela Round'), פונט גדול במיוחד לקריאה קלה.
5. **משוב ויזואלי (Feedback):** אנפשות קלות (Animations/Confetti) בעת הצלחה או סיום משימה.

עצב את רכיבי המסך המרכזי של [שם האפליקציה] לפי קווים מנחים אלו.
```

### 3. סגנון דשבורד ארגוני / עסקי (Corporate Dashboard Style)

**מתי להשתמש?** במערכות ניהול, B2B, או דשבורדים ארגוניים הדורשים צפיפות מידע גבוהה ומראה מקצועי.

```markdown
אתה מעצב ממשקים למערכות enterprise ודשבורדים עסקיים. עצב את [שם האפליקציה] בסגנון ארגוני מתקדם:

### דגשי העיצוב:
1. **מראה נקי ומקצועי (Enterprise Clean):** צפיפות מידע אופטימלית (High Data Density), רקע אפור ניטרלי רך (`#f8fafc` / `#0f172a` במצב כהה).
2. **טיפוגרפיה מובנית:** היררכיה ברורה מאוד, שימוש במספרים מודגשים (Monospace / Tabular Figures לנתונים כספיים).
3. **כרטיסיות וגבולות עדינים:** הפרדה באמצעות גבולות דקים (`border border-slate-200`) וצללים מינימליסטיים.
4. **פלטת צבעים עסקית:** גווני כחול-אפור/טורקיז עמוק לניהול, עם צבעי סטטוס ברורים (Active, Pending, Suspended, Error).
5. **סרגלי ניווט וצד:** תפריט צד (Sidebar) מתקפל, סרגל כלים עליון עם חיפוש מהיר, התראות ופרופיל משתמש.

צור את ה-CSS/Tailwind והרכיבים המרכזיים עבור מסך הניהול הראשי של [שם האפליקציה].
```

### 4. המרת אפליקציה קיימת לאסתטיקה חדשה (Style Migration)

**מתי להשתמש?** כשיש אפליקציה עובדת ורוצים לרענן את ה-UI, לשנות שפת עיצוב או לעבור לעיצוב מודרני מבלי לגעת בלוגיקה.

```markdown
אתה מומחה UI/UX וקוד פרונטאנד. תפקידך להמיר את העיצוב הקיים של [שם האפליקציה] לשפת עיצוב חדשה ומודרנית.

---
### כללי ברזל להמרה:
1. **אפס שינוי בלוגיקה:** שמור על כל שמות ה-State, ה-Handlers, ה-Props והקריאות ל-API בדיוק כפי שהם.
2. **שדרוג ויזואלי בלבד:** החלף את מחלקות ה-CSS / Tailwind והסטיילינג הקיים.
3. **שפת העיצוב החדשה:**
   - פלטת צבעים: [הכנס צבעים חדשים, למשל: Primary `#0d9488`]
   - פינות: [למשל: עגולות מודרניות `rounded-xl`]
   - טיפוגרפיה: [גופן עברי חדיש, מרווחים נקיים]
4. **תמיכה מלאה ב-RTL ובנייד:** ודא שכל המרווחים (padding/margin) משתמשים ב-Logical Properties (למשל `ms-2`, `pe-4`) כדי לתמוך ב-RTL בצורה מושלמת.

קח את הרכיב / המסך הבא והמר אותו לסגנון החדש:
[הדבק כאן את הקוד הקיים]
```

### 5. הגדרת רכיבי UI, מיקרו-אינטראקציות ומצבי קצה

**מתי להשתמש?** לעיצוב הרכיבים הקטנים שעושים את ההבדל: כפתורים, מודאלים, טוסטים ומצבי טעינה.

```markdown
אתה מעצב רכיבי UI ומיקרו-אינטראקציות. צור עבור [שם האפליקציה] מפרט רכיבים מלא (UI Kit Component Specification):

1. **כפתורים (Buttons):**
   - Primary: צבע בולט, מעבר עדין ב-Hover, אפקט Active (לחיצה).
   - Secondary / Outline: גבול דק, רקע שקוף.
   - Danger / Ghost: לפעולות מחיקה / איפוס.
   - מצב Loading (עם ספינר עברי מימין) ומצב Disabled.
2. **כרטיסיות (Cards):** מעבר עדין ברחף (Hover Elevation), שוליים עגולים.
3. **התראות (Toasts / Alerts):** הודעות הצלחה, אזהרה ושגיאה שמופיעות בצד המסך המתאים ל-RTL.
4. **מצבי טעינה (Skeleton Loaders):** שלד טעינה מונפש עבור כרטיסיות וטבלאות במקום ספינר גנרי.

הפק את קוד הרכיבים ב-React / HTML + Tailwind CSS.
```
